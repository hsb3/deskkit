Model · brief D1

D1 — Pointer grammar: what is a pointer allowed to be?

Work items point at documents ("pointer: plan.md § Goals"). The code today accepts a file path with an optional section suffix that gates deliberately ignore, and rejects URLs and #anchors — but no document states any of these rules. Review also found the PM spec promises GitHub-URL pointers that the shipped default gates reject today, so the contradiction is live, not theoretical.

Recommendation: Include — it is the foundation the other model decisions (especially D2) build on.
Model · brief D2

D2 — Typed cross-references: does "graduated to: 42" become a real reference?

Today a graduation marker is a plain string — a bare "42" is valid, and nothing records which repo that issue lives in. The brief lays out whether both products share one typed reference (kind + target + which-repo qualifier), and where the qualifier can live without baking anyone's identity into shipped code.

Recommendation: Include — issue #92's fix treated a symptom; this is the modeling decision underneath it.
Model · brief D3

D3 — Item types: should a typo'd type silently skip every gate?

Creating a work item does not check its type against the known vocabulary. An unknown type matches no gate rules, so the item advances through every phase ungated — re-proven from source during review. The decision: check at creation (hard or warn), or rule the ungated advance deliberate and document it.

Recommendation: Include — small decision, closes a real hole, and the checking machinery already exists for gate config.
Model + workflow · brief D4

D4 — Findings lifecycle: finish the disposition machine and decide what the adoption log is for

The bug floor shipped dispositions (open / acknowledged / triaged / won't-fix), but residue remains: a "dismissed" state no code can set, summary counts that disagree with the findings list, no record of who dispositioned or why — and an adoption log where five of six event kinds are never written. Review confirmed the log does have live readers, so "just delete it" has real blast radius.

Recommendation: Include — #93 fixed the symptom; this rules the complete machine so it stays coherent across every surface.
Surface · brief D5

D5 — Agent contract & parity: one integration contract, two agents (your headline concern)

The librarian and PM agents are built differently on different layers. The brief frames one shared contract (instructions + tool mount + wake layer + write-gate policy) that each agent instantiates, then rules each difference policy or debt: a librarian Claude Code bundle or not; per-module vs shared tool mounts; whether the in-binary loop keeps PM tools it has no instructions for; and the unclaimed tools found on every surface.

Recommendation: Include — this is the decision the session exists for; the model rulings (D1–D4) feed it.
Surface · brief D6

D6 — Prompt governance: which copy of the agent's instructions wins?

Agent instructions exist in three places: compiled into the binary, editable rows in the database, and markdown in the plugin — with no rule about which is the source of truth. Review proved a database edit silently disappears if the store is ever rebuilt. The options: git wins, database wins, or a documented split by prompt class — each with a concrete "reset to shipped" story.

Recommendation: Include — the stale librarian prompt found in Phase 0 is the live proof this is ungoverned.

Recommendation: Include — cheap to rule, and it closes the last spec/reality residue from #94.
