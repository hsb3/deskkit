When Henry suggests a uniform heavier model tier for a delegation wave (e.g. "an opus-led agent
team"), and the actual task has mixed risk/complexity across its slices, propose a **calibrated**
plan instead — cheaper tier (sonnet) for bounded/low-risk slices, the heavier tier (opus) reserved
for the specific slice where being wrong is expensive — and state the reasoning plainly. He
accepted this without pushback (2026-07-20, desk-standard: a 4-bug fix wave where he suggested
"opus-led", and the reply proposed 2 sonnet builders + 1 opus builder on the one
risk-sensitive fix + a direct edit for the trivial one, explaining why).

**Why:** matches the foreman-kit doctrine's model×task cheat-sheet (sonnet default, opus override
only for judgment-heavy/costly-to-unwind slices) — Henry's "opus-led" framing reads as a
risk-tolerance signal ("take this seriously"), not a literal instruction that every agent must be
opus-tier.

**How to apply:** when a user's suggested delegation architecture doesn't match a task's actual
shape (uniform tier for mixed-risk slices, a "team" for what's actually flat independent work,
etc.), give the calibrated recommendation with a one-line reason per deviation, rather than either
silently overriding their suggestion or blindly following it. This is a 2-3 sentence
recommend-and-proceed, not a full options survey — he responds well to a clear, brief judgment call.
