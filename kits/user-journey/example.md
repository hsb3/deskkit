# User journey — Author publishes a note (with assistant collaboration)

## Persona & goal

**Who**: Robin, author. Writes deeply about AI, tech, and process. Works in bursts; gets distracted by shiny ideas; values quality over speed.

**Goal**: Robin has a finished note on "why agent workflows need explicit state machines." He wants to polish it collaboratively with an assistant, ensure it's discoverable (right slug, topics, cross-links), and ship it to his readers.

## Journey

| Step | What they do | What they see | Emotional state | Friction points | System response |
|---|---|---|---|---|---|
| 1 | Opens editor with draft note | CodeMirror 6 with markdown, right sidebar showing polish suggestions | Focused; glad the assistant already flagged a few things | None | System shows last-saved state + agent suggestions from before |
| 2 | Skims agent-proposed edits (title, cross-links, TL;DR) | Three suggestion cards in right panel with diffs, "accept / reject / edit" buttons | Cautious; wants to review before auto-applying | One suggestion feels out of scope (adding a code example); rejects it | System updates suggestions in real-time as Robin accepts/rejects |
| 3 | Spends 20 minutes editing the body directly, tightening prose | Markdown in main editor; cursor position preserved; no distracting suggestions while actively typing | In the zone; flow state | Autocomplete keeps triggering; turns it off mid-edit | Inline ⌘K assist is available if Robin wants to ask assistant ("does this para work?") |
| 4 | Types ⌘K to ask assistant about a specific paragraph | Chat panel opens with context (the paragraph + surrounding prose) | Collaborative; values the realtime feedback | Chat takes a moment to appear (network latency on first load) | Assistant (live) responds in < 30 seconds with suggestions |
| 5 | Applies inline edits from assistant via accept buttons in the chat | Edits merge back into the document smoothly; diff view shows before/after | Satisfied; the collaboration felt natural | Briefly confused which version was accepted (UI could be clearer) | Document updates; version history captures the exchange |
| 6 | Assigns topics: "AI", "process", "state-machines" | Topic dropdown auto-suggests; Robin picks three | Confident in discoverability | Slight friction: searches for "workflows" but it's not a canonical topic; has to use "process" instead | System infers backlinks based on topics and past entries |
| 7 | Reviews the autogenerated pull-quote and OG card preview | Small card appears showing how the note will look when shared | Proud of the framing; it captures the essence | No friction | System shows preview in light and dark mode |
| 8 | Clicks "Publish now" button in the top bar | Dialog asks "ready?" with a preview of publication metadata | Slight anxiety: once it's public, he can't take it back | None (dialog is clean and minimal) | System moves entry status to `published`, sends newsletter to subscribers, posts to social if configured |
| 9 | Views the live entry on the reader surface | Feed shows it; entry detail page is live; related entries are linked at the bottom | Relief and mild pride; the piece is out in the world | None | Readers can now access the entry; it appears in search and topics index |

## Pain points highlighted

- **Step 3 autocomplete distraction**: Autocomplete UI interrupts flow state during active editing. Robin had to manually disable it. Assistant agent's ⌘K assist is opt-in, which feels right; autocomplete is too aggressive.
- **Step 4 chat latency**: First time opening the chat panel, there's a visible delay (network cold start). Subsequent messages are instant, but the initial "hello" moment feels sluggish.
- **Step 6 topic discovery**: Robin instinctively searched for "workflows" as a topic. The system uses canonical topics ("process" instead). No affordance helped him discover the canonical name; he had to guess.

## Opportunities for improvement

- **Smarter autocomplete tuning**: Only trigger autocomplete when Robin pauses typing for >1 second, not on every keystroke. Or make it a sidebar suggestion like the agent polish cards.
- **Warm up the chat connection on editor load**: If Robin is in `developing` status, initialize the chat socket in the background so it's ready if he presses ⌘K. Eliminates the perceived latency.
- **Topic search with aliases**: Show aliases or related terms when Robin types a search. "workflows" could hint at "process" topic. Or allow free-form tags and auto-promote frequent ones to canonical topics over time.
- **Delight moment in publication**: The publish dialog is functional but austere. A brief celebration (confetti, "live to 47 readers") would give Robin positive reinforcement.
